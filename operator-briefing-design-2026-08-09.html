Operator Briefing

One factual, on-demand answer to: what is running, what genuinely needs Geo, what changed, and where should work resume?

Scope: a text-first Brief me page inside Operator, immutable Briefing History, and optional browser read-aloud. No Telegram, scheduled alerts, microphone, new dictation, always-on narration, or AI model calls.

The important distinction

Operator currently marks every settled in-progress turn as awaiting_input. That means the “N need you” count mixes real blocking questions with ordinary turns that are merely ready for review, failures, and old sessions.

Needs your decisionOnly unresolved structured questions. Highest priority and always expanded.
Problems to reviewCurrent errors or failed tool outcomes, safely summarized.
Active nowTasks with a running turn and their latest meaningful activity.
Ready for reviewSettled ordinary turns. Sessions older than seven days collapse under “Older open sessions.”

The page

Top bar: Brief me→/brief→One factual API response→Task/project deep links

Six sections

  1. Needs your decision — exact unresolved questions and waiting time.
  2. Problems to review — current failures without raw stack traces or secrets.
  3. Active now — running tasks and last meaningful activity.
  4. Ready for review — recent settled turns, with stale sessions collapsed.
  5. Since your last briefing — new, active, waiting, changed, merged, or updated tasks proven by snapshot comparison.
  6. Where to pick up — up to five recent projects using stored recaps or latest-task fallback.

The first briefing uses the previous 24 hours for recent activity. Every later briefing compares with the immediately preceding stored briefing.

Never overwrite a briefing

  • Every generated briefing is an immutable point-in-time record.
  • /brief shows the newest briefing and paginated Briefing History.
  • /brief/<id> permanently reopens a specific earlier briefing.
  • Opening or refreshing /brief does not create duplicates; New briefing creates the next record.
  • No automatic pruning or delete route exists in the first release.
  • Artifacts gains a Briefings collection shortcut, but global briefings are not forced into task-owned artifact rows.

Read aloud

  • Starts only when Geo presses Read aloud.
  • Uses browser speech synthesis; system dictation remains the input method.
  • Reads server-provided safe text, not raw errors, paths, tool output, URLs, or ids.
  • Provides Stop and cancels when leaving the page.
  • Disappears when the browser does not support speech synthesis.

Architecture

PartResponsibility
lib/briefing.tsBounded database reads, safe tool-message parsing, classification, ordering, snapshot diff, sanitization, and deterministic speech text.
POST /api/briefingsBuilds and transactionally inserts one immutable briefing; concurrent clicks resolve to one committed successor.
GET /api/briefingsReturns bounded, newest-first history metadata.
GET /api/briefings/<id>Returns stored content without recalculating it.
/brief and /brief/<id>Responsive latest/history and permanent detail pages with deep links and read-aloud controls.
briefings tableStores versioned content, factual snapshots, safe speech text, prior-brief link, counts, and generation time. No transcript text in snapshots.
No AI call in version one. Operator already has enough structured facts. Deterministic output is faster, cheaper, easier to test, and cannot invent task state.

Safety and failure behavior

  • Corrupt tool JSON is ignored; the page uses the next safe fallback.
  • Missing recaps fall back to the most recently touched task.
  • An invalid prior snapshot becomes a first briefing instead of an error.
  • A failed insert never presents an unarchived result as permanent.
  • Historical records have no update/delete endpoint.
  • A speech error never affects the text page.
  • Transcript-derived fields are stripped, bounded, and rendered as React text.
  • Deprecated projects and suggested tasks are excluded.

Verification gate

  • Pure unit tests for question, failure, active, ready, stale, ordering, sanitization, and snapshot comparison.
  • Route tests for immutable generation, concurrent-click deduplication, history pagination, permanent detail, and no delete/update route.
  • Component tests for loading, error, empty, populated, overflow, links, and speech start/stop/unmount.
  • Integrated desktop and phone-width checks through the existing Tailscale Operator origin.
  • Real-state smoke test proving a structured ask is a decision while an ordinary settled turn is only ready for review.

Explicitly not included

Telegram, SMS, email, Slack, push delivery, schedules, new browser notifications, microphone input, transcription, always-on narration, a native Mac companion, model-generated prose, personas, custom voices, manual briefing deletion/editing/sharing, or automatic cleanup of stale tasks.

Success

Geo can open one page on desktop or phone and, in under a minute, distinguish real decisions from ordinary ready turns, see what is active, understand proven changes since the previous briefing, jump directly to the right project or task, and reopen any prior briefing later.
