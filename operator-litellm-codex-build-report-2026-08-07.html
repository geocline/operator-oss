Built

  • Native Codex picker includes GPT-5.6 Sol, Terra, and Luna.
  • Operator refreshes /model/info and admits only explicitly tagged coding models.
  • Model aliases are dynamic; changing the provider model in LiteLLM requires no Operator rework.
  • Removed or malformed models fail closed, while the last-known-good catalog remains available during a gateway outage.
  • The task model picker and Settings both include refresh controls.
  • Gateway credentials are isolated behind a loopback relay; child processes never receive the real LiteLLM or OpenRouter key.
  • Sessions use a separate Codex home and append a content-free, mode-0600 index for future Conversation Dashboard discovery.

Separate billing

Set OPENROUTER_OPERATOR_API_KEY only in LiteLLM and reference it from the Operator-tagged deployment. OpenRouter can then report Operator usage independently.

Activation remaining

Add a real Operator-tagged model and the dedicated provider key, validate and reload LiteLLM, then press Refresh models in Operator. No paid model was added or called during this build.

Next independent phase

The Claude-harness route remains the next build. It should be a separate driver and isolated Claude home behind the same catalog and credential boundary—not a change to native Claude Code. Conversation Dashboard and Card Tracker ingestion of the new session index are also separate integrations.
