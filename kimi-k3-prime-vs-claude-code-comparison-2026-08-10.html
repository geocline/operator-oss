Where Prime looks meaningfully different

Persistent executable IPython state

Observed

Prime routes repository operations through a persistent notebook kernel. Variables, parsed data, helper functions, and intermediate state can survive across tool calls. Claude used granular Read/Edit/Bash calls; each Bash invocation was a fresh shell.

Full Kimi context declaration

Observed configuration

Prime exposed Kimi’s 1,048,576-token context. Claude Code reported 200,000 tokens for the same custom model. That suggests Claude may plan or compact around a smaller window, but a direct context-pressure probe is still needed.

More efficient tool loop on this task

Observed

Prime reached a more complete fix with 11 fewer tool calls, 5 fewer model calls, 62% less time, and 46% lower cost. The stateful notebook may be part of that advantage, although more paired tasks are needed to isolate cause.

Native continual harness refinement

Documented · not yet tested

Prime bundles a workflow that proposes and rolls back changes to its own harness state. Claude Code offers skills, hooks, agents, and configuration. Official OpenAI documentation also describes Codex skills and scored improvement loops, so Prime’s uniqueness is not established; the Codex leg must test the practical difference.

Cleaner custom-model cost attribution

Observed

Prime’s harness cost, generation sum, and key delta matched exactly. Claude Code overestimated both runs by 66.7% and incurred small key-billed overhead not linked to a streamed generation.

Better requirement coverage here

Observed

Prime followed the prompt beyond what the existing tests covered and removed the artifact-notice timestamp. Claude trusted the visible tests and incorrectly concluded that system-notice handling was already intact.

Where Claude Code is stronger or more mature

Granular, legible tool audit

Observed

Read, Edit, and Bash events clearly expose what was inspected and changed. Prime’s general-purpose notebook is powerful but less semantically explicit.

Broad built-in tool surface

Exposed, partly used

The clean session advertised dedicated editing, worktree, task, scheduling, web, skill, and subagent tools. This run used only Read, Edit, and Bash.

Permissions and safe mode

Observed configuration

Claude Code provides well-developed permission modes and a single safe-mode switch for disabling personal customizations while retaining core tools.

Resume and interrupt UX

Documented · not activated

The CLI exposes resume/continue and its event stream advertised interrupt capabilities. Prime’s abort and resume were actually exercised in compatibility testing, so Prime currently has stronger evidence—not necessarily a unique feature.
