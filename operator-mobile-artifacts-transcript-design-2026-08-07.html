Approved design · August 7, 2026

Operator Mobile Artifacts and Durable Transcript

One private Operator URL for every deliberately published deliverable, plus a transcript where Geo can always find, timestamp, and copy both sides of the conversation.

Core decision

Build this into Operator, not a second repository or server.

Operator already supplies the authenticated phone-accessible origin, persistent server, project and task identities, and conversation context. The new capability adds a global artifact registry and repairs the missing transcript affordances in the same release.

The finished experience

Publish in ordinary language

Geo says “Publish that artifact” or “Publish report.html.” The agent calls the built-in publish_artifact tool and returns a stable Open button and copyable link.

Find everything globally

/artifacts lists every deliberately published artifact newest-first, with search, file type, local time, project tag, and task tag.

Return to the source task

The task tag deep-links to /?project=<id>&task=<id>. Browser Back returns to the artifact library.

Trust the transcript

Main-box submissions and question-card answers both become permanent “You” entries. Every human and assistant prose section shows time and a Copy button.

Publishing flow

Geo asks for publication→Agent calls tool→Operator validates and snapshots→Artifact card appears→Phone opens stable URL

Publishing is explicit. Operator will not scan repositories or automatically collect every HTML file, which would pull in app shells, generated output, dependencies, and fixtures.

Durable artifact storage

Published bytes are copied outside repositories and worktrees to <DB_DIR>/artifacts/<artifact-id>/<server-name>. The source can later be deleted or its worktree pruned without breaking the published URL.

Stored metadataPurpose
Artifact, project, task, and generation idsStable identity and exact provenance
Title, filename, MIME type, and byte sizeLibrary display and safe serving
SHA-256 checksumIntegrity and future deduplication
Creation timestampReliable newest-first ordering and local-time display

The first release accepts one file per tool call, up to 10 MB, using Operator’s existing deliverable allowlist: HTML, PDF, Office files, images, text/data formats, SVG, and ZIP.

Safety boundary for HTML

HTML opens inside a sandboxed iframe on an artifact detail page. The content response disables scripts and top navigation, isolates the document from Operator cookies and storage, allows inline styles and ordinary images, and always offers Download original. Script-enabled interactive HTML is intentionally outside the first release.

Transcript changes

  • Existing timestamps are preserved: SQLite already stores created_at; snapshots and live events will stop dropping it.
  • Question answers become first-class entries: after a live answer is accepted, Operator stores a readable user message tagged ask_answer and keyed by ask id so retry cannot duplicate it.
  • No double-send: a visible live-answer entry is transcript metadata because the structured answer already reached the waiting agent. If the live ask is gone, the fallback normal resume remains the only agent input.
  • No user collapse: user entries are never condensed. Assistant tool machinery may remain condensed, but every assistant prose section retains its own timestamp and Copy control.

Copy behavior

  • Every user and assistant message has a Copy button.
  • Whole-message copy returns readable source text and Markdown URLs, without speaker names, timestamps, or UI labels.
  • Every fenced code block has a separate Copy button that copies code only.
  • Touch controls remain visible and finger-sized; desktop controls may be visually quiet until hover or focus.
  • Success briefly reports “Copied.” Failure is visible and leaves the text selectable.

Routes and navigation

RouteResponsibility
GET /api/artifactsRecent-first metadata feed with bounded search, type filter, and pagination
GET /api/artifacts/<id>Single artifact metadata
GET /api/artifacts/<id>/contentAuthenticated, constrained inline preview
GET /api/artifacts/<id>/downloadOriginal bytes with safe attachment filename
POST /api/internal/agent-tools/publish-artifactAuthenticated bridge used by Codex-style harnesses

Failure behavior

  • A failed publication never modifies the source file.
  • File-copy and database-insert failures are rolled back best-effort so no false library entry remains.
  • Missing stored bytes show an unavailable state without exposing a filesystem path.
  • A question answer is not shown as saved unless persistence succeeds; populated controls remain available for retry.
  • Artifact-feed errors show Retry without breaking the rest of Operator.

Verification required

The release is not complete until the following are verified:

  • Traversal and symlink escapes are rejected; worktree removal does not break published files.
  • HTML cannot run a script, navigate Operator, or access its authenticated origin state.
  • Main-box messages and question-card answers survive reload with exact timestamps.
  • Live answers reach the agent exactly once and retries do not duplicate transcript entries.
  • Message and code copy work with mouse, keyboard, and touch.
  • Claude, native Codex, and LiteLLM Codex all receive the publish tool.
  • The full Operator verification suite and production build pass.

Not in this release

No separate artifact server, automatic filesystem scanning, public sharing, folders, custom tags, in-browser editing, version comparison, script-enabled HTML, or automatic import of old files.

Implementation slices

  1. Artifact schema, storage, and publish-domain function.
  2. Agent tool and portable bridge.
  3. Authenticated routes and safe preview.
  4. Global mobile artifact library and deep links.
  5. Timestamp propagation and rendering.
  6. Durable, idempotent question-answer transcript entries.
  7. Message-level and code-block copy controls.
  8. Integrated mobile, security, and regression verification.
