Why this fits the system

  • No provider credentials or real-model catalog in Operator.
  • A new model appears after one LiteLLM edit and one refresh.
  • Unrelated or special-purpose models remain invisible.
  • Stable aliases can move to newer models without touching existing tasks.

Required guardrails

  • Only enable models that pass a coding-agent compatibility probe.
  • Separate text/coding models from image-generation models.
  • Keep the last-known catalog when LiteLLM is temporarily unavailable.
  • Show the resolved physical model after every turn.
Harness and model are separate choices

Recommended refinement: route × harness × model

The harness supplies the agent loop and tools. The route determines subscription versus metered API access. The model supplies the intelligence. Operator should model all three explicitly while showing only valid combinations.

Switching before a task starts

Route, harness, and model can be changed freely. Operator resets incompatible reasoning and permission settings exactly as it already does when switching between Claude and Codex.

Switching after a session starts

A Claude session ID cannot be resumed by Codex, and the reverse is also true. Operator must use its existing handoff flow: summarize the current generation, open a fresh native session in the same worktree, and seed it with the carried context.

Preserved behavior

  • Claude Code continues using Geo’s existing subscription and native transcript store.
  • Codex continues using Geo’s existing subscription and native transcript store.
  • The new driver does not modify either existing driver’s endpoint, authentication, models, or sessions.
  • Operator still exposes its worktree, tools, streaming events, and task controls consistently.

Cross-project additions

  • Conversation Dashboard gains an operator source and archive folder.
  • Card Tracker’s database constraint, API validation, badges, search, and links gain “Operator.”
  • Operator deep links replace a misleading CLI resume command for gateway-backed sessions.
  • Compatibility checks prevent an unsuitable tagged model from starting a coding session.
Approved implementation order

Codex harness first, Claude Code harness second

Phase Outcome Primary systems

Catalog guarantees

  • Refresh is server-side and never exposes LiteLLM’s raw deployment configuration.
  • A failed refresh keeps the last-known-good catalog.
  • A removed selected model is marked unavailable and never silently replaced.
  • Compatibility tests are explicit and paid inference never runs merely because Geo clicked Refresh.

Security and billing guarantees

  • The OpenRouter Operator key lives only inside LiteLLM.
  • Operator receives only a loopback gateway client credential.
  • The implementation must prove that shell tools cannot read the gateway credential.
  • OpenRouter’s dedicated key is the authoritative chargeback record; Operator labels exact cost only when the response path provides it reliably.
End-to-end acceptance
  1. Add and tag a model in LiteLLM using the dedicated Operator provider key.
  2. Refresh Operator and see only valid Operator-tagged choices.
  3. Verify a chosen model/harness combination with an explicit read-only test.
  4. Run a real task with files, terminal tools, worktree edits, Stop/resume, and handoff.
  5. Find the session under the Operator source in Conversations Dashboard.
  6. Archive it, search it from Card Tracker, attach it, and open the exact Operator task.
  7. Confirm native Claude Code and Codex still use their original subscriptions and session stores.
