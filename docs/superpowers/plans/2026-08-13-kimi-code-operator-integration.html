Kimi Code Operator Integration Plan

For agentic workers: execute every implementation task test-first and run independent review before paid admission.

Goal: Add Kimi Code as a fourth public harness and admit only exact passing Kimi K3/DeepSeek pairings.

Architecture: Official TypeScript SDK over the pinned official Wire CLI; secret-free inline provider plus temporary environment route through Operator’s relay; per-task state; shared Operator tool implementations; normalized StreamEvent output.

Task 1 — Catalog and package surface

  1. Add failing tests for kimi-code admission parsing, public driver registration, empty-before-admission model list, Auto-run-only permissions, refresh path, and unavailable executable behavior.
  2. Add exact SDK/CLI dependencies and config/env defaults.
  3. Implement the new harness value and capability/registry/API mappings; run focused tests.

Task 2 — Isolated policy and environment

  1. Add failing tests for task-local home, path traversal rejection, credential scrubbing, relay-only credential exposure, telemetry disablement, exact alias/context/reasoning variables, and no persisted key.
  2. Implement kimi-code/policy.ts; run focused tests.

Task 3 — Event normalizer

  1. Add recorded/constructed SDK event tests for text, thinking, tool call/result pairing, usage, subagent notices, approvals, interrupt, errors, and malformed events.
  2. Implement kimi-code/events.ts with bounded diagnostics and fail-closed tool handling; run focused tests.

Task 4 — Operator tools and driver

  1. Add fake-SDK tests for worktree/session/model/env arguments, resume, interactive ask, Operator tool success, abort/close, missing CLI, and no fallback.
  2. Implement external tools and the SDK-backed driver; register it in runtime and SDK-free maps.
  3. Run driver, runner, ask, registry, and API tests.

Task 5 — Packaging and documentation

  1. Add failing packaging tests for exact CLI version, binary verification, runtime home ownership, and environment documentation.
  2. Update Dockerfile, entrypoint, README, architecture docs, .env.example, and package lock.
  3. Run typecheck, focused tests, full tests, build, and build-trace checks.

Task 6 — Independent review and live admission

  1. Request independent review; resolve every Critical/Important issue.
  2. Check provider-key stability read-only.
  3. Run Kimi K3 × Kimi Code admission and write sanitized evidence.
  4. Only if it passes, add exact gateway admission metadata, validate, safely reload, and refresh Operator.
  5. Repeat independently for DeepSeek V4 Pro.
