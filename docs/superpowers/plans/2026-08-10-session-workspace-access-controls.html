Session Workspace and Access Controls Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: use executing-plans and implement every task test-first.

Goal: Give every new Operator task explicit, independent Workspace and Agent access settings, defaulting to Project folder and Full power.

Architecture: Persist workspace intent on the task rather than inferring it from a project at first-message time. Reuse permission_mode for access, but persist the full-power choice explicitly. Render both controls in the New/Edit task sheets and make Codex full power truthful by using danger-full-access.

Tech stack: Next.js 16, React 19, TypeScript, SQLite/better-sqlite3, Vitest.

Task 1: Persist per-task workspace mode

Files: modify lib/db.ts, lib/types.ts, app/orchestrator/types.ts, lib/store.ts; test tests/repoDirect.test.ts.

  1. Add a failing test proving a new task stores workspace_mode: "direct" and an existing task with a worktree migrates to worktree.
  2. Run npm test -- tests/repoDirect.test.ts; expect failure because the field does not exist.
  3. Add workspace_mode TEXT NOT NULL DEFAULT 'direct' to the task schema and migration. On first addition, backfill rows with nonempty worktree_path to worktree.
  4. Add workspace_mode: "direct" | "worktree" to server/client task types, task creation input, SQL insert, and updateTask.
  5. Run the focused test; expect pass.

Task 2: Enforce workspace selection in task APIs

Files: modify app/api/tasks/route.ts, app/api/tasks/[id]/route.ts, app/api/tasks/[id]/messages/route.ts; test tests/repoDirect.test.ts and tests/apiHelpers.test.ts if route helpers are reused.

  1. Add failing route tests proving task creation defaults to direct, accepts worktree, rejects unknown values, and rejects changing workspace after started = 1.
  2. Add a failing first-message test proving worktree creation is controlled only by task.workspace_mode, not project.run_in_repo.
  3. Run the focused tests and verify the expected failures.
  4. Validate workspace_mode at POST/PATCH boundaries. Permit PATCH only before start and before a worktree exists.
  5. Change first-message setup to call ensureWorktree only for workspace_mode === "worktree".
  6. Run focused tests; expect pass.
