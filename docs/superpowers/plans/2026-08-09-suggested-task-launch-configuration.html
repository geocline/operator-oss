Suggested Task Launch Configuration Implementation Plan

Inline execution plan for the approved design and consolidation of the existing dirty change set.

GoalRequire explicit Harness, Model, and Thinking strength confirmation before an agent-created suggested task can start. ArchitecturePersist launch requirements on the task, validate confirmation through the task API, enforce it at the initial-message boundary, and render one reusable configuration editor in the edit modal. StackNext.js 16, React 19, TypeScript, SQLite, Vitest, react-test-renderer. ExecutionInline, test-driven, without committing or disturbing unrelated untracked artifacts.

File map

  • lib/types.ts, lib/db.ts, lib/store.ts: durable task fields and migration/backfill.
  • lib/agents/types.ts, app/orchestrator/types.ts, lib/agents/litellm/capabilities.ts: optional model-specific reasoning metadata.
  • app/api/tasks/[id]/route.ts: configuration validation, confirmation, and invalidation.
  • app/api/tasks/[id]/messages/route.ts: authoritative initial-launch gate.
  • app/orchestrator/launchConfig.ts: pure suggestion and option-selection helpers.
  • app/orchestrator/modals.tsx: configuration editor and Confirm setup action.
  • app/orchestrator/useOrchestrator.ts, app/Orchestrator.tsx: save/start wiring and state refresh.
  • app/orchestrator/TasksColumn.tsx, app/orchestrator/TaskBoard.tsx, app/orchestrator/SessionView.tsx: pending-review gating and confirmed summaries.
  • app/globals.css: compact launch-configuration presentation.
  • lib/agentToolDefs.mjs, existing dirty workstream files, and tests: consolidate the earlier permissive-posting decision.
  • app/orchestrator/useDocumentTitle.ts, lib/agents/shared.ts, and tests: finish verification for the earlier tab-title and global-rule work.

Task 1 - Pin the durable launch contract

  1. Write failing store tests asserting suggested tasks receive launch_config_required=1 and launch_config_confirmed_at=0, while ordinary tasks do not require confirmation.
  2. Run the focused test and confirm failure because the fields do not exist.
  3. Add both integer columns to the base schema and idempotent migration. Backfill only existing unstarted rows still marked suggested=1.
  4. Add both fields to server and client task types, createTask, and updateTask.
  5. Run the focused store test and existing task/store suites.
npm test -- tests/suggestedLaunchConfig.test.ts tests/taskReorder.test.ts

Task 2 - Validate confirmation and block bypasses

  1. Write failing route tests for: valid confirmation, unsupported model, unsupported reasoning preset, configuration changes clearing confirmation, and initial launch returning 409 before side effects.
  2. Add a pure server helper that resolves capabilities for the selected agent and validates explicit model/reasoning values.
  3. Extend task PATCH with a confirm_launch_config action. Apply agent/model/reasoning changes and confirmation atomically; clear confirmation on later pre-start configuration changes.
  4. Gate only !started && launch_config_required && !launch_config_confirmed_at in the messages route before claiming a turn or creating a worktree.
  5. Run route tests and confirm the rejected launch has no message, worktree, or running-state side effect.
npm test -- tests/suggestedLaunchConfig.test.ts

Task 3 - Build suggestion helpers and the modal flow

  1. Write failing pure-helper tests for default Harness/Model/Thinking strength resolution and harness changes.
  2. Create launchConfig.ts. Prefer valid explicit values, then agent-scoped reasoning default, then think, then the first supported option.
  3. Extend model capability metadata with optional reasoning-preset values and populate it for LiteLLM catalog models.
  4. Write failing modal tests asserting suggested values render, Confirm setup stays unavailable when capabilities are missing, and confirmation sends title/description/priority/dependencies plus agent/model/reasoning and confirm_launch_config:true.
  5. Add the Harness, Model, and Thinking strength fields to the edit modal for required unstarted tasks. Harness changes refresh dependent choices.
  6. Preserve the existing save timeout/retry behavior and keep edits in the open modal on failure.
