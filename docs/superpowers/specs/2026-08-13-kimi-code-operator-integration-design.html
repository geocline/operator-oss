Kimi Code as Operator’s Fourth Public Harness

Date: August 13, 2026
Status: Approved architecture from the cross-harness handoff, refined against the current official SDK and CLI.

Decision: Add public harness Kimi Code backed by hidden driver litellm-kimi-code. Pin @moonshot-ai/kimi-agent-sdk@0.1.8 and the official Kimi Wire CLI 1.49.0. The originally selected npm CLI 0.36.0 was rejected by the paid-run preflight because it no longer exposes --wire/--work-dir. Route exact Operator aliases through the existing loopback relay using a secret-free inline provider skeleton and Kimi’s non-persisted environment overlay.

Completion budget: set KIMI_MODEL_MAX_COMPLETION_TOKENS=16384 in the supervised child environment. Wire CLI 1.49 otherwise uses the model’s entire remaining context window as the requested completion budget; for a one-million-token model this approaches 930,000 output tokens and can fail provider credit preflight before inference.

Cost evidence: require every relay-captured generation ID to reconcile to one exact physical model and a finite nonnegative provider-reported cost. Record the shared OpenRouter key-usage delta as corroborating diagnostics, not an admission veto: concurrent Operator traffic can increase that account-wide counter, while posting delay can temporarily omit generations that already have attributable provider records.

Boundaries

  • LiteLLM remains hidden infrastructure. The child receives only operator-loopback-relay, never a gateway or OpenRouter credential.
  • Every task gets LITELLM_KIMI_CODE_HOME/<task-id> as KIMI_CODE_HOME; global Kimi configuration, sessions, Skills, and memory are not read.
  • Telemetry is disabled. The model/provider override is in memory and is never written to config.toml.
  • The first public permission surface is Auto-run only. Kimi Code Plan mode is not called a sandbox and remains hidden until its write/Bash/network/subagent/hook behavior is independently proven.
  • The driver remains registered when the executable is unavailable and returns an actionable error; it never falls back to Claude, Codex, or Prime.

Driver architecture

UnitResponsibility
lib/agents/kimi-code/policy.tsValidate task IDs, derive the isolated home, scrub ambient credentials, and build the secret-free inline provider plus exact environment overlay for the selected alias and relay.
lib/agents/kimi-code/events.tsNormalize SDK content, thinking, tool, subagent, usage, approval, interrupt, and unknown events into Operator’s StreamEvent contract. Malformed paired-tool events fail closed.
lib/agents/kimi-code/tools.tsExpose Operator’s scoped tools through the SDK external-tool interface, including an interactive ask_user that parks on Operator’s existing ask registry.
lib/agents/kimi-code/driver.tsCreate/resume an SDK session in the task worktree, stream normalized events, interrupt the active turn on Stop, close the SDK session, and report unavailable-state errors without fallback.
Catalog/API/UI mapsAdd kimi-code to admission metadata and expose one fourth public harness whose models point internally to litellm-kimi-code.

Data flow

  1. Operator selects an exact model admitted for kimi-code.
  2. The driver starts/reuses Operator’s loopback relay and constructs a credential-scrubbed child environment.
  3. The SDK spawns the pinned kimi executable with the task worktree, opaque session ID, Auto-run, isolated home, and temporary OpenAI-compatible model overlay.
  4. SDK events normalize into Operator events; Operator external tools call the same shared implementation used by other harnesses.
  5. Stop invokes the SDK turn interrupt, then session close; admission verifies no Kimi child remains.
  6. Provider generation IDs captured by the relay reconcile physical identity and cost before any gateway admission metadata changes.

Error policy

Unknown informational SDK events are bounded diagnostics. Schema-invalid tool events, approval failures, missing exact model selection, missing executable, and model/provider errors emit actionable errors and no successful completion. Abort is not an error, but must settle the task and child process.

Testing and admission

  • Strict TDD for policy/env isolation, event mapping, external Operator tools, registry/API surface, unavailable behavior, resume, abort, and packaging.
  • Run deterministic fake-SDK tests before installing or invoking the live CLI.
  • Run the reusable admission contract separately for Kimi K3 and DeepSeek V4 Pro.
  • Add kimi-code gateway admission metadata only for an exact passing artifact. A failure changes no catalog semantics.
  • Request independent code review before the first paid Kimi Code admission.
No implicit promotion: implementation makes the harness available, but model options remain empty until a pairing’s sanitized live evidence passes and the gateway is explicitly updated and safely reloaded.
