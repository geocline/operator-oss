# litellm-dsh driver - spec (approved by Geo, 2026-08-16)

Goal: DeepSeek Harness (dsh) as Operator's fifth harness, for DeepSeek-family models, billed through the loopback LiteLLM relay exactly like Prime and Kimi Code. Rationale: harnesses tuned by a lab for its own models perform best (Geo's standing policy in the harness-model routing rules); dsh is DeepSeek's Claude Code.

## What dsh is (from the 2026-08-15 deep dive; clone may still exist at /tmp/deepseek-harness, else `git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness` to consult)

- TypeScript agent harness, npm `@deepseek-ai/dsh`, developer preview - PIN THE EXACT VERSION in package.json and expect breaking changes.
- Programmatic driving: the JSON-RPC stdio SDK - newline-delimited JSON-RPC 2.0. Methods `initialize`, `session/prompt`, `shutdown`; notifications `session.event` (durable session events: turn/step/user/assistant chunks+messages/tool calls+results), `session.status`, `subagent.started/finished`. The server side is the `dsh-sdk-jsonrpc-server` plugin composition; stdout is the protocol channel (any stdout logging corrupts it). `session/prompt` returns an enqueue receipt, not a result - completion is observed via events (turn/end) and idle status.
- Headless composition exists (`dsh-headless` bundle / the BENCHMARK.md "jsonrpc-agent minimal variant"); model providers are configured via its config layers - an OpenAI-compatible provider entry can point at an arbitrary baseUrl, which is how the LiteLLM relay plugs in.
- dsh has an MCP client (`mcp-client` package, stdio servers, tools surface as mcp__server__tool), which is how Operator's orchestrator tools (suggest_task / expose_service / ask_user) attach via the existing stdio bridge scripts/orch-mcp.mjs.

## Deliverables

1. **`lib/agents/dsh/driver.ts`** implementing AgentDriver - only runTurn() is required (one-shot helpers backstopped by the utility agent per the oneshots policy). Follow `lib/agents/prime/driver.ts` as the closest pattern and `lib/agents/kimi-code/` for the pinned-SDK/CLI conventions: id `"litellm-dsh"`, label "DSH (DeepSeek)"; HMR-surviving live-client tracking on globalThis with a settle function for task deletion; task-local state dirs under LITELLM_DSH_HOME (default ~/.operator/litellm-dsh), one child dir per task; per-turn: acquire the LiteLLM relay (getLiteLLMRelay), materialize the dsh profile/config for the task (model provider pointed at the relay baseUrl with the relay child key; MCP entry for scripts/orch-mcp.mjs; telemetry off), spawn the pinned dsh jsonrpc composition over stdio, initialize, session/prompt with the built prompt (buildProjectContext + workstream guidance via shared.ts helpers), stream session.event notifications mapped to StreamEvent, resolve on turn end/idle, record session id (opaque per driver - sessions.claude_session_id column stores it), append the operator session index like Prime does.
2. **`lib/agents/dsh/events.ts`** - pure mapper from dsh session.event payloads to Operator StreamEvents (assistant text deltas -> assistant; tool calls -> tool with ToolData via shared.ts normalizers; tool results -> tool_result; usage; turn_end). Unknown event types ignored safely. Unit-test this against captured/synthetic fixtures - do NOT require a real dsh install in tests (fake CLI fixture at tests/fixtures/dsh/fake-dsh.mjs emitting a scripted JSONL exchange, following tests/fixtures/kimi/fake-kimi-cli.mjs).
3. **`lib/agents/dsh/policy.ts`** - model admission: only DeepSeek-family models (deepseek*, plus whatever the LiteLLM catalog tags with harness "dsh"); reuse isSubscriptionOnlyModelId guard (Anthropic/OpenAI families are already excluded at the catalog choke point - keep it that way). Capabilities via `liteLLMCapabilities("dsh")` (add the harness key; autoRunOnly like prime/kimi; managedCatalogPath /api/agents/litellm-dsh/models/refresh).
4. **Registry + naming**: register in lib/agents/registry.ts; capabilities entry; PUBLIC_AGENT_IDS gains "litellm-dsh" -> "dsh" with label "DSH (DeepSeek)"; app/orchestrator/agents.ts publicHarnessId gains the mapping. No "litellm" string may reach the client (pinned by the existing litellmAgentUi test - extend it).
5. **Config**: LITELLM_DSH_HOME and DSH_CLI_PATH (blank = resolve the pinned package's bin from node_modules) in lib/config.ts + .env.example + tests/setup.ts. package.json: add the exact-pinned `@deepseek-ai/dsh` dependency. Dockerfile: install/COPY the CLI like prime/kimi are shipped (mirror their pattern).
6. **Catalog**: lib/agents/litellm/catalog.ts - "dsh" joins the harness vocabulary; models offered for dsh only when tagged for it, `unvetted` until admission evals run (do NOT run live admission evals in this pass; the existing modelAdmission framework covers it later).
7. **Tests** (no real dsh install, no network): driver contract via the fake CLI (turn runs, events map, transcript persists, stop/settle works - follow tests/kimiCodeDriver.test.ts and tests/agentDriver.test.ts patterns), events mapper unit tests, policy/family guard tests, registry/public-id/capabilities assertions, packaging test if kimi has one (mirror tests/kimiCodePackaging.test.ts).
