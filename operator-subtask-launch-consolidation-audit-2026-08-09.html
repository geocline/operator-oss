Operator Subtask Launch and Consolidation Audit

August 9, 2026 - final state of the requested pre-start model/harness controls and the unfinished work found in the existing dirty checkout.

Outcome

Required launch review

Every agent-created suggested task now requires explicit confirmation of Harness, Model, and Thinking strength before its first turn.

Suggested, not assumed

The editor proposes valid values using the task, harness capabilities, model-specific reasoning options, and agent-scoped defaults. Geo must select Confirm setup.

Durable enforcement

Confirmation is persisted in SQLite and revalidated at the server boundary. List, board, accepted-task hero, stale tabs, catalog changes, and direct requests cannot bypass it.

Implemented behavior

  • Pending cards show Review setup instead of Start.
  • Confirmed cards show Harness · Model · Thinking strength and enable Start only when the harness is connected.
  • Changing Harness, Model, or Thinking strength clears confirmation.
  • Changing Harness refreshes the dependent model and reasoning suggestions.
  • Model-specific Thinking strength limits are honored for catalog-backed LiteLLM routes.
  • Add keeps the confirmation requirement when moving a suggestion into the normal task list.
  • Unavailable or removed models return the task to Review setup.
  • The initial-message API validates before launch and again after waiting for the task lock.
  • A live first-turn claim rejects concurrent launch-configuration edits, closing the final stale-configuration race found in review.
  • Fresh-install tutorial suggestions and existing unstarted rows still in the Suggested tray are also gated.
  • Ordinary user-created tasks keep their existing start flow.
