Controlled harness experiment

One model. Three harnesses. Measured call by call.

Kimi K3 stays fixed while Prime Agent, Codex, and Claude Code perform the same work. The experiment measures correctness, tools, recovery, time, tokens, and exact OpenRouter cost.

Design for Geo · August 9, 2026 · No installation or paid test has been performed

Read-only validation results

Kimi K3 is the control

1,048,576-token context, always-on reasoning, image input, and tool use. The local gateway already exposes the exact route as operator.kimi-k3.

Claude Code can attempt it

The CLI supports arbitrary gateway model names and LiteLLM's Anthropic-format endpoint. Anthropic does not support non-Claude models, so compatibility must be proven rather than assumed.

OpenRouter is measurable

The existing Operator key can report its own spend. Each model response can include prompt, completion, reasoning, cache, generation, latency, and exact cost data.

Current balance: the observed OpenRouter account snapshot leaves approximately $13.18. The experiment will report spend after every task and will not purchase credits automatically.

Selected approach

Quick smoke

Three tasks once. Cheap, but too vulnerable to one unlucky run.

Fixed full benchmark

Five tasks twice. Stronger, but wastes credits on obvious failures.

Adaptive paired evaluation

Compatibility gates, five matched tasks, then repeat only close or anomalous results. Best evidence per dollar.

Five matched tasks

1 · Architecture

Inspect an unfamiliar repository and produce a fact-checked architecture brief with valid paths.

2 · Debugging

Reproduce, diagnose, and repair a seeded bug; targeted and full tests must pass.

3 · Feature work

Implement a bounded feature from a realistic specification without unrelated changes.

4 · Research

Use available tools to reach a cited, source-supported decision.

5 · Continuity

Handle a correction, interruption, resume, and completion without stale assumptions or repeated work.

Separate · Refinement

Prime Agent alone receives a before/refine/after/rollback sequence. This is not mixed into its cold score.

Decision gates

  1. Prove each harness reaches Kimi K3 without fallback.
  2. Prove read-only tools, usage, Stop, and resume.
  3. Run the five cold tasks once per compatible harness.
  4. Repeat only close, suspicious, or recoverable failures while credits permit.
  5. Run Prime Agent's separate longitudinal refinement test.
  6. Publish the evidence as an HTML recommendation: reject, revisit, Labs integration, or production candidate.
